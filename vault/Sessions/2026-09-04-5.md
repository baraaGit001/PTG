# 2026-09-04 (5)

Two reported defects: admin **Community** was a red error card, and the web
**Health** tab didn't lead to the app's Health screen.

## Did

**Fixed the admin Community page — and every other community endpoint with it.**
`GET /admin/community/posts?page=1&pageSize=20` returned
`400 VALIDATION_ERROR: "property page should not exist"`. This is
[[../Decisions/0004-no-type-only-imports-for-injectables]] again: the earlier
sweep missed two files.
[community.controller.ts](../../apps/api/src/modules/community/community.controller.ts)
and
[admin-wallet.controller.ts](../../apps/api/src/modules/wallet/admin-wallet.controller.ts)
still pulled their DTO classes in with `import type`, so `emitDecoratorMetadata`
wrote `Function` into `design:paramtypes` and `ValidationPipe` validated
against a class with no metadata — `forbidNonWhitelisted` then rejected every
field. Both are value imports now.

The blast radius was wider than the one page: the public feed
(`/community/posts?page=…`) was equally broken, as were create-post, comment,
react, report, moderate, resolve-report, and the five admin wallet/bonus
writes. Only the *unparameterised* calls happened to work, which is why it
looked like one bad screen.

**Added a regression guard.**
[runtime-imports.spec.ts](../../apps/api/test/runtime-imports.spec.ts) walks
`apps/api/src` and fails if any `@Body`/`@Query`/`@Param` parameter type — or
any constructor-injected class — comes from a type-only import. Verified it
actually catches the bug by reverting one import: 9 offenders reported, then
restored. ESLint can't see this dependency (that's *why* the rule is off for
the API), so a test is the only thing that can hold the line.

**Health tab went to the wrong screen.** `GUEST_PRIMARY_NAV` in
[navigation.ts](../../packages/config/src/navigation.ts) pointed *Health* at
`/health/knowledge`, so a signed-out visitor tapping Health got the article
list — not the app's Health screen. The hub at `/health` was already a faithful
copy of the app (dark Today's Overview card, Health Management, Community +
Sport Ranking, Health Knowledge); nothing ever routed guests to it. Now
`/health`, with `matchPrefix` so the tab stays lit on the sub-pages.

**Rebuilt Health Management to match the app.**
[health-management-page.tsx](../../apps/web/src/features/health/health-management-page.tsx)
was a generic two-column form asking for "Weight (grams)". The app's screen is
a **Basic Profile** card (Height cm · Weight kg · Gender segmented control ·
Date of Birth), a **Health Goals** card (Current Goal · Daily Activity ·
Target Weight), and one dark full-width **Save Profile** button. Weights stay
grams in the API and cross the boundary through `toKg`/`toGrams`. New i18n
keys translated across all five locales.

## Verified

- `pnpm typecheck`, `pnpm lint` clean; `pnpm test` 48 pass (36 api — up from
  33 — 9 web, 3 admin).
- Browser (430×932): guest taps Health → lands on `/health` with Today's
  Overview rendering. Admin `/community` lists the seeded post, no error card.
- Health Management round-trip: 175 cm / 78.4 kg / Male / 1991-02-01 /
  Lose Weight / Sedentary / 72 kg saved and read back identically after a
  reload — the decimal survives the kg↔grams conversion.

## Decided

Nothing new — this session was ADR 0004 being enforced rather than revisited.
Worth noting the trap has now bitten twice, hence the test.

## Open questions / follow-ups

- **The app's Health Management has a "Quick Actions" row** (three tiles) below
  Save Profile. It's cut off in the store screenshot and its destinations are
  unknowable from the outside, so it was left out rather than invented.
- **Gender toggle shows Male/Female only**, matching the app, but the enum also
  has `OTHER`/`UNSPECIFIED`. A profile holding one of those renders with
  neither pill selected until the user picks — deliberate (it doesn't silently
  rewrite stored data), but it looks unset.
- **The seeded health profile is empty** (no height/weight), so the screen
  first renders blank. Fine, but a seeded profile would demo better.
- Everything still open from [[2026-09-04-4]] stands: fractional PV, seven
  products on placeholder artwork, unconfirmed OCUZ pricing, the thin
  Fulfillment Orders screen, missing quick-add-to-cart / sort tabs /
  cart select-all.
- Running `pnpm dev` twice leaves orphaned watchers holding 5173/5174/3001;
  Vite's `strictPort` then kills the whole parallel run. Killing every stray
  `node.exe` before `pnpm dev` is currently the workaround.
